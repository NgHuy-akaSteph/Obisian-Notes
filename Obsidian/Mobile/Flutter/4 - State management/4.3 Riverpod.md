### 1. Kiến thức cốt lõi
#### 1.1 Providers
- `Provider` là một hàm có nhớ (memoized functions): trả về giá trị được lưu lại (cache) với cùng tham số đầu vào.
- `Provider` bọc (wrapper) hàm và sẽ lưu lại (cache) dữ liệu và cho phép những `widget` khác truy cập vào với cùng giá trị.
- `Provider` cũng cung cấp các khả năng sau:
	- Cơ chế vô hiệu hóa cache tích hợp: `Ref.watch` 
	- Tự động hủy (disposal): `Provider` có thể tự động giải phóng nếu không còn cần thiết
	- Ràng buộc dữ liệu (data-binding): 
		- Thay vì dùng `FutureBuilder` hoặc `StreamBuilder` vốn làm code UI rất rối và lồng ghép nhiều lớp, `Riverpod` cho phép xử lý Future/Stream ngay trong `Provider`
		- Lợi ích: UI của chỉ cần dùng `ref.watch().when()` để hiển thị các trạng thái: loading, error, data.
	- Tự động xử lý lỗi: `Riverpod` (đặc biệt với `AsyncValue`) giúp gom nhóm các trường hợp lỗi vào một chỗ. Không cần phải dùng khối try-catch lặp đi lặp lại trong UI. `Provider` sẽ bắt lỗi và đẩy thông báo đó xuống UI một cách hệ thống.
	- Hỗ trợ kiểm thử (Mocking support): `Riverpod` cho phép ghi đè (override) một Provider bằng một giá trị giả (mock) chỉ dành riêng cho bài test đó mà không cần thay đổi code thực tế của ứng dụng.
	- Lưu trữ ngoại tuyến (Offline persistence): lưu lại kết quả của Provider xuống bộ nhớ máy. <mark style="background: #FF5582A6;">(Thử nghiệm - experimental)</mark>
	- Thay đổi dữ liệu (Mutations): đây là cách `Riverpod` xử lý các side effects (VD: bấm nút Gửi, Cập nhật thông tin,...). <mark style="background: #FF5582A6;">(Thử nghiệm - experimental)</mark>

- `Provider` cung cấp 6 biến thể:
- Unmodifiable: Provider, FutureProvider, StreamProvider
```dart
final userDaoProvider = Provider((ref) => UserDao());  
final sessionDaoProvider = Provider((ref) => SessionDao());  
  
// Provider cung cấp UserRepository  
final userRepositoryProvider = Provider<UserRepository>((ref) {  
  final userDao = ref.watch(userDaoProvider);  
  final sessionDao = ref.watch(sessionDaoProvider);  
  return UserRepository(userDao, sessionDao);  
});
```
	
- Modifiable: NotifierProvider, AsyncNotifierProvider, StreamNotifierProvider
- NotifierProvider: dùng cùng với Notifier - class tạo ra state có thể thay đổi theo thời gian
	- Dùng khi trạng thái là đồng bộ (synchronous) -> giá trị khởi tạo sẵn mà không cần dùng await
```dart
class AuthNotifier extends Notifier<AuthState> {  
  @override  
  AuthState build() {  
    return const AuthState(status: AuthStatus.initial);  
  }
}


final authProvider = NotifierProvider<AuthNotifier, AuthState>(  
  () => AuthNotifier(),  
);
```

- AsyncNotifierProvider: dùng cùng với AsyncNotifier - tương tự Notifier nhưng dùng khi khởi tạo bất đồng bộ (asynchronous)
	- Dùng khi trạng thái khởi tọa là bất đồng bộ (asynchronous) -> build() dùng async - await và trả về một Future 
	- AsyncValue giúp quản lý 3 trạng thái của UI: data (có dữ liệu), loading (đang tải), error (lỗi). 
```dart
/// todo_notifier.dart
class TodoNotifier extends AsyncNotifier<List<TodoModel>> {  
  // 1. Phương thức build: tải dữ liệu ban đầu  
  @override  
  Future<List<TodoModel>> build() async {  
    // Watch repository (Giống Dependency Injection)  
    final repository = ref.watch(todoRepositoryProvider);  
    return repository.getAllTodos();  
  }
  // Hàm getAllTodos() là một hàm bất đồng bộ.
}

final todoNotifierProvider =  
    AsyncNotifierProvider<TodoNotifier, List<TodoModel>>(() {  
      return TodoNotifier();  
    });
    

/// todo_screen.dart
Expanded(  
	// Dùng when và bắt buộc phải xử lý cả 3 trạng thái của state -> Sự đảm bảo khi dùng AsyncValue
  child: todosAsync.when(  
    loading: () => const Center(child: CircularProgressIndicator()),  
    error: (err, stack) => Center(child: Text('Error: $err')),  
    data: (todos) {  
      if (todos.isEmpty) {  
        return const Center(child: Text(Strings.emptyTodoListLabel));  
      }  
      return ListView.builder(  
        padding: const EdgeInsets.symmetric(vertical: 8.0),  
        itemCount: todos.length,  
        itemBuilder: (context, index) {  
          return TodoItemTile(todo: todos[index]);  
        },  
      );  
    },  
  ),  
),

```
#### 1.2 Consumers
- Consumer là một loại widgets có quyền truy cập vào Ref, cho phép cung cấp và lắng nghe thay đổi.
- ConsumerWidget : là biến thể tương ứng của StatelessWidget, có tính năng tương tự nhau nhưng hàm build() có thêm tham số WidgetRef
```dart
class TodoScreen extends ConsumerWidget {  
  const TodoScreen({super.key});  
  
  @override  
  Widget build(BuildContext context, WidgetRef ref) {  
    final todosAsync = ref.watch(filteredTodosProvider);
    //....
  }
}
```
- ConsumerStatefulWidget: là biến thể tương ứng với StatefulWidget. Thay vì kế thừa State, ta sẽ kế thừa ConsumerState và trong ConsumerState có sẵn thuộc tính ref
```dart
class SignInScreen extends ConsumerStatefulWidget {  
  const SignInScreen({super.key});  
  
  @override  
  ConsumerState<SignInScreen> createState() => _SignInScreenState();  
}  
  
class _SignInScreenState extends ConsumerState<SignInScreen> {  
  @override  
	Widget build(BuildContext context) {  
	  // Có sẵn ref để sử dụng 
	  ref.listen<AuthState>(authProvider, (previous, next) {  
		if (next.errorMessage != null && next.errorMessage!.isNotEmpty) {  
		  ScaffoldMessenger.of(context).showSnackBar(  
			SnackBar(  
			  content: Text(next.errorMessage!),  
			  backgroundColor: Colors.redAccent,  
			  behavior: SnackBarBehavior.floating,  
			),  
		  );  
		}  
	  });
}
```
#### 1.3 ProviderContainers/ProviderScopes
- `ProviderContainer` là trung tâm của kiến trúc Riverpod. Trong Riverpod, Provider không giữa state của chúng mà toàn bộ state được lưu trữ bên trong đối tượng ProviderContainer.
```dart
import 'package:riverpod/riverpod.dart';

// Tạo một ProviderContainer trong main và có thể đọc và sửa provider
void main() {
  final container = ProviderContainer();

  try {
    final sub = container.listen(counterProvider, (previous, next) {
      print('Counter changed from $previous to $next');
    });
    print('Counter starts at ${sub.read()}');
  } finally {
    // Dispose the container when done
    container.dispose();
  }
}
```
- `ProviderScope` là một widget có thể tạo `ProviderContainer` và hiển thị trong widget tree. Vì trong Flutter không thể sử dụng trực tiếp ProviderContainer.
```dart
oid main() async {  
  // Bọc ngoài Widget root
  runApp(ProviderScope(child: const MyApp()));  
}
```

### 3. Xử lý lỗi
#### 3.1 Lỗi version
- Đọc lỗi (Decoding): Tìm từ khóa `Because`, `depends on...`. Xác định thư viện nào đòi phiên bản mới, thư viên nào đòi phiên bản cũ.
- Kiểm tra tại [Pub.dev](https://pub.dev/) : tìm phiên bản trung gian nào của thư viện mới hỗ trợ thư viện cũ (analyzer) không.
- Hạn version: hạ phiên bản của thư viện gây xung đột xuống mức an toàn nhất.
- Dùng `dependency_overrides`: Ép buộc dự án dùng chung một phiên bản thư viên cốt lõi (thường là `analyzer`).

- Các lệnh thường dùng sau khi thay đổi version:
```cmd
# 1. Xóa file lock
rm pubspec.lock  (hoặc xóa tay)
rm -rf .dart_tool (hoặc xóa tay)

# 2. Chạy clean
flutter clean
flutter pub get

# 3. Build lại
dart run build_runner build --delete-conflicting-outputs
```

- Lưu ý:
	- Chạy watch để theo dõi việc generate: `dart run build_runner watch -d`
	- Sửa lỗi Android Studio: Menu File -> Invalidate Caches... -> Invalidate and Restart. Hoặc chuột phải vào thư mục lib -> Reload from Disk

#### 3.2 Lỗi NDK: 
- Tìm và xóa thư mục NDK, sau đó chạy lại flutter run (Flutter sẽ tự động tải và cài lại NDK)
