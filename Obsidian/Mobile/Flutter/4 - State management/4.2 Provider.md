### 4.2.1 InheritedWidget
1. Định nghĩa: 
	- Là một Widget cơ bản được tích hợp sẵn trong Flutter Framework (không cần cài thêm thư viện)
2. Vai trò: 
	- Vận chuyển dữ liệu từ trên xuống dưới trong cây Wiget (Down the tree) mà không cần truyền qua Constructor của từng Widget trung gian.
3. Cơ chế hoạt động:
	- Đăng ký: Wiget con gọi `context.dependOnInheritedWidgetOfExactType<T>()` để đăng ký lắng nghe.
	- Thông báo: Khi Wiget cha (kế thừa InheritedWidget) được build lại với dữ liệu mới, nó chạy hàm `updateShoudNotify()`
	- Lọc: Nếu `updateShouldNotify()` trả về true -> Báo tất cả Widget con đã đăng ký phải vẽ lại.
4. Cấu trúc Wrapper
	- InheritedWidget là immutable, các biến trong nó đều là final và không thay đổi sau khi khởi tạo (Đóng vai trò là xe vận chuyển). Để thay đổi dữ liệu, ta buộc phải hủy bỏ InheritedWidget cũ và tạo ra một InheritedWiget mới với dữ liệu mới. Do đó, ta cần một StatefullWidget bọc ngoài (Wrapper).
	- Cơ chế:
		- StatefulWidget giữ biến (State) có thể thay đổi (Mutable)
		- Khi cần thay đổi dữ liệu -> Gọi setState()
		- Hàm build chạy lại -> Tạo ra một InheritedWidget **mới** chứa dữ liệu mới nhât.
		- Widget con bên dưới lắng nghe thay đổi -> Vẽ lại giao diện
5. Phân tích ví dụ
- B1: Xây dựng InheritedWidget để truyền state
```dart
  
import 'package:flutter/material.dart';  
  
/// Lop Inherited dung de truyen state  
class AuthInherited extends InheritedWidget {  
  final bool isLoading;  
  final String? username;  
  final Function(String) onLogin; // truyen ham de update  
  
  const AuthInherited({  
    super.key,  
    required super.child,  
    required this.isLoading,  
    this.username,  
    required this.onLogin  
  });  
  
  // Ham nay quyet dinh khi nao widget con can ve lai  
  // covariant: ep kieu cha chung chung ve kieu con cu the  @override  
  bool updateShouldNotify(covariant AuthInherited oldWidget) {  
    return isLoading != oldWidget.isLoading || username != oldWidget.username;  
  }  
  
  // Khong bat buoc phai tao o day, co the de trong giao dien  
  // Viec tao o day giup code sach va de kiem soat hon viec check null  
static AuthInherited? of(BuildContext context) {  
    final result = context.dependOnInheritedWidgetOfExactType<AuthInherited>();  
    return result;  
}  
  
}
```
- B2: Xây dựng lớp Wrapper 
```dart
  
import 'package:flutter/material.dart';  
  
import 'auth_inherited.dart';  
  
/// Lop Wrapper luu tru state  
class AuthWrapper extends StatefulWidget {  
  final Widget child;  
  const AuthWrapper({super.key, required this.child});  
  
  @override  
  State<AuthWrapper> createState() => _AuthWrapperState();  
}  
  
class _AuthWrapperState extends State<AuthWrapper> {  
  bool _isLoading = false;  
  String? _username;  
  
  void _login(String username) async {  
    print('1. Start');  
    setState(() {  
      _isLoading = true;  
    });  
    print('2. Login');  
    await Future.delayed(const Duration(seconds: 2)); // Gia lap api  
    setState(() {  
      _isLoading = false;  
      _username = username;  
    });  
    print('3. End');  
  }  
  
  @override  
  Widget build(BuildContext context) {  
    return Scaffold(  
      body: Center(  
        child: AuthInherited(  
            isLoading: _isLoading,  
            username: _username,  
            onLogin: _login,  
            child: widget.child),  
      ),  
  
    );  
  }  
}
```
- B3: Xây dựng giao diện
```dart
import 'package:flutter/material.dart';  
  
import 'auth_inherited.dart';  
  
/// Giao dien login can dung state  
class LoginScreen extends StatelessWidget {  
  const LoginScreen({super.key});  
  
  @override  
  Widget build(BuildContext context) {  
    // Đăng ký lắng nghe thay đổi của AuthInherited  
    // helper function of trong auth_inherited.dart    final authData = AuthInherited.of(context)!;  
  
    if (authData.isLoading) return Center(child: const CircularProgressIndicator());  
    if (authData.username != null) return Center(child: Text('Hello, ${authData.username}'));  
  
    return ElevatedButton(  
      onPressed: () => authData.onLogin('Huy Quang'),  
      child: const Text('Login'),  
    );  
  }  
}
```
### 4.2.2 Cốt lõi
1. Cài đặt
	- Chạy lệnh này ở terminal tại thư mục gốc: `flutter pub add provider`
2. Nguyên lý
	- Bản chất là lớp vỏ bọc (wrapper) của `InheritedWidget`, giúp đơn giản hóa việc truyền dữ liệu và quản lý vòng đời (lifecycle)
	- Cơ chế hoạt động
		- B1: Tạo kho: Khởi tạo dữ liệu ở đỉnh cây Widget (hoặc trên Widget cần dùng)
		- B2: Truyền xuống : Dữ liệu được truyền xuống dưới các thành phần trong cây Widget.
		- B3: Lắng nghe: Widget con đăng ký nhận thông báo để vẽ lại dữ liệu thay đổi.
	- Dependency Injection(DI)): giúp tách biệt code logic ra khỏi UI
3. Thành phần
	- Logic (Model):
		- `ChangeNotifier`: Class chứa dữ liệu và logic
		- `notifyListeners()`: hàm báo sự thay đổi -> không có thì thay đổi không được lắng nghe
	- Nơi cung cấp (Provider):
		- `ChangeNotifierProvider`: dùng cho state có thể thay đổi (phổ biến nhất)
			- Tham số `create()`: nơi tạo logic (VD: `(_) => AuthProvider()`)
			- Tham số `lazy`: mặc định là true (chỉ khởi tạo khi có người dùng đến)
			- Tham số `child`: Widget được áp dụng (Có thể là toàn app hoặc Widget cụ thể)
		- `MultiProvider`: Dùng để gộp nhiều Provider lại, tránh code bị lồng nhau
		- `FutureProvider`: : Dùng cho dữ liệu bất đồng bộ 1 lần (gọi API, đọc file config)
		- `StreamProvider`: Dùng cho luồng dữ liệu liên tục (Socket, Firebase)
		- `ProxyProvider`: Dùng khi Provider này phụ thuộc Provider kia (Riverpod giải quyết vấn đề này tốt hơn)
4. Cách sử dụng
	- `context.watch<T>()`: lắng nghe, rebuild lại Widget khi dữ liệu thay đổi -> Dùng trong hàm build của Widget.
	- `context.read<T>()`: đọc 1 lần, không rebuild lại Widget -> Dùng trong các sự kiện onPressed, onTap, initState.
	- `Consumer<T>`: giống `context.watch` nhưng chỉ rebuild phần Widget con nằm trong builder -> Khoanh vùng phạm vi rebuild.
