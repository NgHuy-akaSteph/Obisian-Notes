### 1. Kiến thức cốt lõi
#### 1.1 Providers
- `Provider` là một hàm có nhớ (memoized functions): trả về giá trị được lưu lại (cache) với cùng tham số đầu vào.
- `Provider` bọc (wrapper) hàm và sẽ lưu lại (cache) dữ liệu và cho phép những `widget` khác truy cập vào với cùng giá trị.
- `Provider` cũng cung cấp các khả năng sau:
	- Cơ chế vô hiệu hóa cache tích hợp: `Ref.watch` 
	- Tự động hủy (disposal): `Provider` có thể tự động giải phóng nếu không còn cần thiết
	- Ràng buộc dữ liệu (data-binding): 
		- Thay vì dùng `FutureBuilder` hoặc `StreamBuilder` vốn làm code UI rất rối và lồng ghép nhiều lớp, `Riverpod` cho phép xử lý Future/Stream ngay trong `Provider`
		- Lợi ích: UI của chỉ cần dùng `ref.watch().when()` để hiển thị các trạng thái: loading, error, data.
	- Tự động xử lý lỗi: `Riverpod` (đặc biệt với `AsyncValue`) giúp gom nhóm các trường hợp lỗi vào một chỗ. Không cần phải dùng khối try-catch lặp đi lặp lại trong UI. `Provider` sẽ bắt lỗi và đẩy thông báo đó xuống UI một cách hệ thống.
	- Hỗ trợ kiểm thử (Mocking support): `Riverpod` cho phép ghi đè (override) một Provider bằng một giá trị giả (mock) chỉ dành riêng cho bài test đó mà không cần thay đổi code thực tế của ứng dụng.
	- Lưu trữ ngoại tuyến (Offline persistence): lưu lại kết quả của Provider xuống bộ nhớ máy. <mark style="background: #FF5582A6;">(Thử nghiệm - experimental)</mark>
	- Thay đổi dữ liệu (Mutations): đây là cách `Riverpod` xử lý các side effects (VD: bấm nút Gửi, Cập nhật thông tin,...). <mark style="background: #FF5582A6;">(Thử nghiệm - experimental)</mark>

- `Provider` cung cấp 6 biến thể:
- Unmodifiable: Provider, FutureProvider, StreamProvider
```dart
final userDaoProvider = Provider((ref) => UserDao());  
final sessionDaoProvider = Provider((ref) => SessionDao());  
  
// Provider cung cấp UserRepository  
final userRepositoryProvider = Provider<UserRepository>((ref) {  
  final userDao = ref.watch(userDaoProvider);  
  final sessionDao = ref.watch(sessionDaoProvider);  
  return UserRepository(userDao, sessionDao);  
});
```
	
- Modifiable: NotifierProvider, AsyncNotifierProvider, StreamNotifierProvider
- NotifierProvider: dùng cùng với Notifier - class tạo ra state có thể thay đổi theo thời gian
	- Dùng khi trạng thái là đồng bộ (synchronous) -> giá trị khởi tạo sẵn mà không cần dùng await
```dart
class AuthNotifier extends Notifier<AuthState> {  
  @override  
  AuthState build() {  
    return const AuthState(status: AuthStatus.initial);  
  }
}


final authProvider = NotifierProvider<AuthNotifier, AuthState>(  
  () => AuthNotifier(),  
);
```

- AsyncNotifierProvider: dùng cùng với AsyncNotifier - tương tự Notifier nhưng dùng khi khởi tạo bất đồng bộ (asynchronous)
	- Dùng khi trạng thái khởi tọa là bất đồng bộ (asynchronous) -> build() dùng async - await và trả về một Future 
	- AsyncValue giúp quản lý 3 trạng thái của UI: data (có dữ liệu), loading (đang tải), error (lỗi). 
```dart
/// todo_notifier.dart
class TodoNotifier extends AsyncNotifier<List<TodoModel>> {  
  // 1. Phương thức build: tải dữ liệu ban đầu  
  @override  
  Future<List<TodoModel>> build() async {  
    // Watch repository (Giống Dependency Injection)  
    final repository = ref.watch(todoRepositoryProvider);  
    return repository.getAllTodos();  
  }
  // Hàm getAllTodos() là một hàm bất đồng bộ.
}

final todoNotifierProvider =  
    AsyncNotifierProvider<TodoNotifier, List<TodoModel>>(() {  
      return TodoNotifier();  
    });
    

/// todo_screen.dart
Expanded(  
	// Dùng when và bắt buộc phải xử lý cả 3 trạng thái của state -> Sự đảm bảo khi dùng AsyncValue
  child: todosAsync.when(  
    loading: () => const Center(child: CircularProgressIndicator()),  
    error: (err, stack) => Center(child: Text('Error: $err')),  
    data: (todos) {  
      if (todos.isEmpty) {  
        return const Center(child: Text(Strings.emptyTodoListLabel));  
      }  
      return ListView.builder(  
        padding: const EdgeInsets.symmetric(vertical: 8.0),  
        itemCount: todos.length,  
        itemBuilder: (context, index) {  
          return TodoItemTile(todo: todos[index]);  
        },  
      );  
    },  
  ),  
),

```
#### 1.2 Consumers
- Consumer là một loại widgets có quyền truy cập vào Ref, cho phép cung cấp và lắng nghe thay đổi.
- ConsumerWidget : là biến thể tương ứng của StatelessWidget, có tính năng tương tự nhau nhưng hàm build() có thêm tham số WidgetRef
```dart
class TodoScreen extends ConsumerWidget {  
  const TodoScreen({super.key});  
  
  @override  
  Widget build(BuildContext context, WidgetRef ref) {  
    final todosAsync = ref.watch(filteredTodosProvider);
    //....
  }
}
```
- ConsumerStatefulWidget: là biến thể tương ứng với StatefulWidget. Thay vì kế thừa State, ta sẽ kế thừa ConsumerState và trong ConsumerState có sẵn thuộc tính ref
```dart
class SignInScreen extends ConsumerStatefulWidget {  
  const SignInScreen({super.key});  
  
  @override  
  ConsumerState<SignInScreen> createState() => _SignInScreenState();  
}  
  
class _SignInScreenState extends ConsumerState<SignInScreen> {  
  @override  
	Widget build(BuildContext context) {  
	  // Có sẵn ref để sử dụng 
	  ref.listen<AuthState>(authProvider, (previous, next) {  
		if (next.errorMessage != null && next.errorMessage!.isNotEmpty) {  
		  ScaffoldMessenger.of(context).showSnackBar(  
			SnackBar(  
			  content: Text(next.errorMessage!),  
			  backgroundColor: Colors.redAccent,  
			  behavior: SnackBarBehavior.floating,  
			),  
		  );  
		}  
	  });
}
```
#### 1.3 ProviderContainers/ProviderScopes
- `ProviderContainer` là trung tâm của kiến trúc Riverpod. Trong Riverpod, Provider không giữa state của chúng mà toàn bộ state được lưu trữ bên trong đối tượng ProviderContainer.
```dart
import 'package:riverpod/riverpod.dart';

// Tạo một ProviderContainer trong main và có thể đọc và sửa provider
void main() {
  final container = ProviderContainer();

  try {
    final sub = container.listen(counterProvider, (previous, next) {
      print('Counter changed from $previous to $next');
    });
    print('Counter starts at ${sub.read()}');
  } finally {
    // Dispose the container when done
    container.dispose();
  }
}
```
- `ProviderScope` là một widget có thể tạo `ProviderContainer` và hiển thị trong widget tree. Vì trong Flutter không thể sử dụng trực tiếp ProviderContainer.
```dart
oid main() async {  
  // Bọc ngoài Widget root
  runApp(ProviderScope(child: const MyApp()));  
}
```

- Tại sao phải lưu trữ trạng thái (state) trong 1 container?
	- No global state
	- Separation of concerns: 
		- Nếu Riverpod cho phép Provider lưu trữ state của riêng chúng, điều này cho phép bất cứ thứ gì có thể đọc/ghi vào state đó -> Không thể kiểm soát cách thức/ thời điểm một state được sửa đổi.
		- Với Riverpod, các state được quản lý tập trung: Tất cả logic để sửa đổi Provider được thực hiện trong chính Provider đó. Còn với UI chỉ cần gọi 1 phương thức trên Notifier của Provider cần dùng.
	- Better testing: Việc lưu trữ state trong 1 container giúp ta không phải bận tâm về việc reset ứng dụng giữa các tests. Ta chỉ cần tạo các container riêng biệt cho mỗi test -> tạo state mới với mỗi Provider.
	- A centralized place for configuring your application: cấu hình các khía cạnh của app. VD: định nghĩa một custom ProviderObserver để lắng nghe tất cả sự thay đổi trạng thái trong app.
	- Support for Scoping providers: cho phép cùng một Provider resolve những state khác nhau phụ thuộc vào vị trí trong widget tree. (Đây là tính năng nâng cao và không được khuyến khích nhưng hữu ích cho việc tối ưu hiệu suất).
#### 1.4 Refs
- `Refs` là cách chinh để tương tác với `Providers`.
- `Refs` khá tương tự `BuildContext` trong Flutter nhưng là cho Provider thay vì Widgets. 
- Một vài tính năng có thể dùng với ref:
	- đọc/quan sát state của một provider
	- kiểm tra provider hiện đang được tải 
	- reset state của 1 provider.

- Provider có thể truy cập Ref như là 1 tham số của hàm khởi tạo hoặc thuộc tính của lớp Notifier
```dart
final myProvider = Provider<int>((ref) {
  // ref is available here
  ...
});

final myNotifierProvider = NotifierProvider<MyNotifier, int>(MyNotifier.new);

class MyNotifier extends Notifier<int> {
  @override
  int build() {
    // this.ref is available anywhere inside notifiers
    ref.watch(someProvider);
    ...
  }
}
```

- Để có được Ref trong widgets thì cần sử dụng Consumer
```dart
Consumer(
  builder: (context, ref, _) {
    // ref is available here
    final value = ref.watch(myProvider);
    return Text('$value');
  },
);
```

- Nếu không ở trong Widget/Provider thì có thể sử dụng loosely connected đến một widget/provider.
```dart
void myFunction(WidgetRef ref) {
  // You can pass the ref around!
}

...

Consumer(
  builder: (context, ref, _) {
    return ElevatedButton(
      onPressed: () => myFunction(ref), // Pass the ref to your function
      child: Text('Click me'),
    );
  },
);
```

- Ref.watch: là cách 'declarative' để lắng nghe 1 provider: gọi `ref.watch(Provider)`, widget sẽ đăng ký với Provider và sẽ rebuild mỗi khi Provider thay đổi -> Giống việc dùng `InheritedWidget` trong Flutter
```dart
Consumer(  
builder: (context, ref, _) {  
	final tick = ref.watch(tickProvider);  
	return Text('Tick: $tick');  
},  
);

final isDivisibleBy4 = Provider<bool>((ref) {  
	final tick = ref.watch(tickProvider);  
	return tick % 4 == 0;  
});
```
  
 - Ref.listen: là cách thủ công để lắng nghe provider, giống cách dùng phương thức `addListener` hoặc phương thức `Stream.listen`. Dùng để biểu hiện side-effect khi provider thay đổi, VD: showing a dialog, logging a message,...
 ```dart
 final exampleProvider = Provider<int>((ref) {
  ref.listen(tickProvider, (previous, next) {
    // This is called whenever tickProvider changes
    print('Tick changed from $previous to $next');
  });

  return 0;
});

Consumer(
  builder: (context, ref, _) {
    ref.listen(tickProvider, (previous, next) {
      // This is called whenever tickProvider changes
      print('Tick changed from $previous to $next');
    });
  
    return Text('Listening to tick changes');
  },
);
 ```

- Ref.invalidate: reset state của 1 provider: bỏ qua trạng thái hiện tại và re-evaluate (đánh giá lại) ở lần tiếp theo provider được gọi.
```dart
Consumer(
  builder: (context, ref, _) {
    return ElevatedButton(
      onPressed: () {
        // Reset the tick provider
        // This will restart the tick from 0
        ref.invalidate(tickProvider);
      },
      child: Text('Reset Tick'),
    );
  },
);
```

- Ref.read: dùng để tương tác với state của Provider trong button.
```dart
Consumer(
  builder: (context, ref, _) {
    return ElevatedButton(
      onPressed: () {
        // Read the current tick value
        final tick = ref.read(tickProvider);
        print('Current tick: $tick');
      },
      child: Text('Print Tick'),
    );
  },
);
```

- Không dùng Ref.read với ý nghĩa tối ưu bằng cách tránh Ref.watch -> Mã nguồn dễ gãy (brittle), sự thay đổi state của Provider có thể không đồng bộ với UI. Nên dùng Ref.watch hoặc sử dụng select:
```dart
Consumer(
  builder: (context, ref, _) {
    // ❌ Don't use "read" as a mean to ignore changes
    final tick = ref.read(tickProvider);

    // ✅ Use "watch" to listen to changes.
    // This shouldn't be a bottle-neck in your apps. Do not over-optimize.
    final tick = ref.watch(tickProvider);

    // ✅ Use "select" to only listen to the specific part of the state you care about
    final isEven = ref.watch(
      tickProvider.select((tick) => tick.isEven),
    );

    ...
  },
);
```

- Ref.onDispose(): dùng để dọn dẹp tài nguyên khi Provider không còn sử dụng
	- Ứng dụng: Đóng các stream, hủy timer, xóa dữ liệu tạm thời để tránh memory leak.
	- Tự động hóa: Riverpod tự động dọn dẹp các listener khi Provider được reset (VD: khi gọi ref.invalidate)
#### 1.5 Automatic disposal
- Riverpod có thể báo cho framework để tự động hủy tài nguyên liên quan đến một provider khi nó ko còn được sử dụng.
- Nếu không muốn dùng automatic disposal thì sử dụng `isAutoDispose: true` khi tạo Provider.
	- Khi provider nhận tham số thì nên sử dụng tự hủy, nếu không một trạng thái cho mỗi tổ hợp tham số sẽ được tạo ra -> memory leak.
	- 
```dart
final helloWorldProvider = Provider<String>(
  // Opt-in to automatic disposal
  isAutoDispose: true,
  (ref) => 'Hello world!',
);
```

- Buộc hủy theo cách thủ công: Dùng ref.invalidate sẽ hủy trạng thái hiện tại của provider và có 2 TH xảy ra:
	- Nếu provider được lắng nghe, state mới sẽ được tạo.
	- Nếu provider không được lăng nghe, provider sẽ bị hủy hoàn toàn
- Provider có thể tự vô hiệu chính nó bằng `ref.invalidateSelf`.
- Khi dùng các Provider có tính năng `autoDispose`, trạng thái sẽ bị hủy ngay khi không còn listenernào sau 1 frame. Tuy nhiên, khi dùng `ref.keepAlive()` để yêu cầu Riverpod giữ lại trạng thái này (ví dụ: chỉ giữ lại kết quả nếu request thành công, còn thất bại thì cho phép hủy).
- Hủy trạng thái có điều kiện: Bạn có thể sử dụng giá trị trả về từ `ref.keepAlive()` (thường được đặt là link) và gọi `link.close()` để khôi phục hành vi tự động hủy (auto-dispose) khi cần thiết.
```dart
final provider = FutureProvider.autoDispose<String>((ref) async {
  final response = await http.get(Uri.parse('https://example.com'));
  // We keep the provider alive only after the request has successfully completed.
  // If the request failed (and threw an exception), then when the provider stops being
  // listened to, the state will be destroyed.
  final link = ref.keepAlive();

  // We can use the `link` to restore the auto-dispose behavior with:
  // link.close();

  return response.body;
});
```

```dart
// Triển khai một extension để dễ dùng và tái sử dụng
extension CacheForExtension on Ref {
  /// Keeps the provider alive for [duration].
  void cacheFor(Duration duration) {
    // Immediately prevent the state from getting destroyed.
    final link = keepAlive();
    // After duration has elapsed, we re-enable automatic disposal.
    final timer = Timer(duration, link.close);

    // Optional: when the provider is recomputed (such as with ref.watch),
    // we cancel the pending timer.
    onDispose(timer.cancel);
  }
}


// Sử dụng trong provider
final provider = FutureProvider.autoDispose<Object>((ref) async {
  /// Keeps the state alive for 5 minutes
  ref.cacheFor(const Duration(minutes: 5));

  return http.get(Uri.https('example.com'));
});
```
#### 1.6 Family
- Family là một tính năng mạnh mẽ của Riverpod, cho phép 1 provider được liên kết với nhiều trạng thái độc lập, dựa trên một tổ hợp tham số. (asimilated to a Map)
- Tạo một provider sử dụng family:
```dart
// Nhận vào id của todo
final todoDetailsProvider = Provider.family<TodoModel?, String>((ref, id) {  
  final todoAsync = ref.watch(todoNotifierProvider);  
  
  return todoAsync.maybeWhen(  
    data: (todos) => todos.firstWhere((t) => t.id == id),  
    orElse: () => null,  
  );  
});

// Sử dụng để build detail cho 1 todo
class TodoDetailsScreen extends ConsumerWidget {  
  final String todoId;  
  
  const TodoDetailsScreen({super.key, required this.todoId});  
  
  @override  
  Widget build(BuildContext context, WidgetRef ref) {  
	  // Tuyền tham số id để lấy được todo
    final todo = ref.watch(todoDetailsProvider(todoId));
    //...
  }
}
```

#### 3.1 Lỗi version
- Đọc lỗi (Decoding): Tìm từ khóa `Because`, `depends on...`. Xác định thư viện nào đòi phiên bản mới, thư viên nào đòi phiên bản cũ.
- Kiểm tra tại [Pub.dev](https://pub.dev/) : tìm phiên bản trung gian nào của thư viện mới hỗ trợ thư viện cũ (analyzer) không.
- Hạn version: hạ phiên bản của thư viện gây xung đột xuống mức an toàn nhất.
- Dùng `dependency_overrides`: Ép buộc dự án dùng chung một phiên bản thư viên cốt lõi (thường là `analyzer`).

- Các lệnh thường dùng sau khi thay đổi version:
```cmd
# 1. Xóa file lock
rm pubspec.lock  (hoặc xóa tay)
rm -rf .dart_tool (hoặc xóa tay)

# 2. Chạy clean
flutter clean
flutter pub get

# 3. Build lại
dart run build_runner build --delete-conflicting-outputs
```

- Lưu ý:
	- Chạy watch để theo dõi việc generate: `dart run build_runner watch -d`
	- Sửa lỗi Android Studio: Menu File -> Invalidate Caches... -> Invalidate and Restart. Hoặc chuột phải vào thư mục lib -> Reload from Disk

#### 3.2 Lỗi NDK:
